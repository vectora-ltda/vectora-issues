# Vectora Issues

Public intake for Vectora bugs, feature requests, UX feedback, and documentation improvements.

[🇺🇸 English](README.md) · [🇧🇷 Português](README.pt-BR.md) · [🇲🇽 Español](README.es-MX.md)

## How it works

- Issues can be opened here or through the Vectora Company issue page.
- The Company synchronizes titles, descriptions, comments, labels, assignments, and state through the GitHub API and webhooks.
- CodeRabbitAI can enrich new issues and generate an implementation plan with `@coderabbitai plan`.
- An approved request receives the `approved-for-core` label and can be promoted to the main `vectora-ltda/vectora` repository through an authenticated workflow.
- Promotion preserves backlinks between the public request and the core issue and prevents duplicate records.

## Opening an issue

Search existing issues first. Include the current behavior, expected behavior, reproduction steps, Vectora version, environment, and redacted evidence where relevant. Never publish tokens, keys, passwords, or personal data. Use the private security channel for vulnerabilities.

## Triage states

`needs-triage` means the request awaits analysis. `planned` means a technical plan exists. `approved-for-core` authorizes promotion to the main repository. `duplicate`, `invalid`, and `wontfix` close triage with an explicit reason.
